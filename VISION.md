# Songarr vision

Songarr should feel like asking for music, not operating a download system.

A user may know only a track title, an artist and album, or a vague combination of details. They submit what they know. Songarr does the work asynchronously and asks for a decision only when multiple songs, releases, or formats are meaningful possibilities.

A good experience:

1. Submit a partial request.
2. See it move through the queue without waiting for downloads.
3. Choose among clear human-readable candidates when needed.
4. See the preferred format honored when available.
5. See transient failures retry automatically.
6. Delete a request when it is no longer wanted.

Songarr is intentionally not trying to become a complete music-management platform. Playlists, catalog ownership, indexers, download clients, and detailed quality-profile management remain outside the current product.

The long-term success case is that Lidarr adopts this workflow and Songarr can disappear.
